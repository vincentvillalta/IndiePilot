Stand up the two GitHub Actions workflows that gate PRs and exercise the Drizzle schema against real Neon branches:
1. **`.github/workflows/ci.yml`** — typecheck + lint + test on every PR and push to main; required to merge.
2. **`.github/workflows/neon-branch.yml`** — per-PR Neon preview branch lifecycle: create on PR open/sync, apply migrations, comment on PR; delete on PR close.

Use the verbatim RESEARCH "Code Examples" workflows. Provision the Neon API key + project ID as GitHub secrets/variables. Configure branch protection so neither workflow can be bypassed on merges to main.

Purpose: FOUND-03 — every Drizzle migration we write in Phases 1-7 is exercised against a fresh, isolated Neon branch on every PR. Combined with `db:migrate` over `db:push` (Pitfall 2 mitigation), this gives us a per-PR audit trail and zero confidence loss when Phase 2's KMS schema lands.

Output: A repo where opening any PR shows two GitHub status checks (CI + Neon Preview Branch), where the migrations actually run against a real Neon branch (not mocked), and where stale `pr-*` branches don't accumulate.

    ```yaml
    name: Neon Preview Branch

    on:
      pull_request:
        types: [opened, reopened, synchronize, closed]

    jobs:
      setup:
        if: github.event.action != 'closed'
        runs-on: ubuntu-latest
        permissions:
          contents: read
          pull-requests: write
        steps:
          - uses: actions/checkout@v4

          - uses: pnpm/action-setup@v4
            with: { version: 10 }

          - uses: actions/setup-node@v4
            with:
              node-version: 20
              cache: 'pnpm'

          - run: pnpm install --frozen-lockfile

          - name: Create Neon branch for PR
            id: create-branch
            uses: neondatabase/create-branch-action@v5
            with:
              project_id: ${{ vars.NEON_PROJECT_ID }}
              branch_name: pr-${{ github.event.number }}
              api_key: ${{ secrets.NEON_API_KEY }}

          - name: Apply migrations
            env:
              DATABASE_URL: ${{ steps.create-branch.outputs.db_url_with_pooler }}
            run: pnpm db:migrate

          - name: Comment branch info on PR
            uses: actions/github-script@v7

              script: |
                github.rest.issues.createComment({
                  owner: context.repo.owner,
                  repo: context.repo.repo,
                  issue_number: context.issue.number,
                  body: `Neon preview branch \`pr-${context.issue.number}\` ready. Migrations applied.`,

        if: github.event.action == 'closed'
        runs-on: ubuntu-latest
        steps:
          - name: Delete Neon branch
            uses: neondatabase/delete-branch-action@v3
    ```

    **Step 3: `.github/workflows/neon-branch-watchdog.yml`** — RESEARCH Pitfall 5 mitigation (belt-and-suspenders cleanup):
    ```yaml
    name: Neon Branch Watchdog

    # Daily sweep: list pr-* branches and delete any whose PR is closed/merged.
    # Belt-and-suspenders for Pitfall 5 — workflow gates that miss the close event.

    on:
      schedule:
        - cron: '0 3 * * *'   # 03:00 UTC daily
      workflow_dispatch:

    jobs:
      sweep:
        runs-on: ubuntu-latest
        permissions:
          contents: read
          pull-requests: read
        steps:
          - name: List Neon pr-* branches and delete orphans
            env:
              NEON_API_KEY: ${{ secrets.NEON_API_KEY }}
              NEON_PROJECT_ID: ${{ vars.NEON_PROJECT_ID }}
              GH_TOKEN: ${{ github.token }}
              REPO: ${{ github.repository }}
            run: |
              set -euo pipefail
              # 1. List all Neon branches matching pr-*
              branches=$(curl -fsS \
                -H "Authorization: Bearer ${NEON_API_KEY}" \
                "https://console.neon.tech/api/v2/projects/${NEON_PROJECT_ID}/branches" \
                | jq -r '.branches[] | select(.name | startswith("pr-")) | .name')

              if [[ -z "${branches}" ]]; then
                echo "No pr-* branches to check."
                exit 0
              fi

              # 2. For each, check the PR state via gh CLI; delete if closed or non-existent.
              for branch in ${branches}; do
                pr_num="${branch#pr-}"
                state=$(gh pr view "${pr_num}" --repo "${REPO}" --json state --jq '.state' 2>/dev/null || echo "MISSING")

                if [[ "${state}" == "MERGED" || "${state}" == "CLOSED" || "${state}" == "MISSING" ]]; then
                  echo "Deleting orphaned Neon branch ${branch} (PR #${pr_num} state: ${state})"
                  curl -fsS -X DELETE \
                    -H "Authorization: Bearer ${NEON_API_KEY}" \
                    "https://console.neon.tech/api/v2/projects/${NEON_PROJECT_ID}/branches/${branch}" \
                    || echo "Failed to delete ${branch} — may already be gone"
                else
                  echo "Keeping ${branch} (PR #${pr_num} state: ${state})"
                fi
              done
    ```
    The watchdog runs at 03:00 UTC daily and via manual dispatch. Catches the pathological case where the PR `closed` event was missed.
